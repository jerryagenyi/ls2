## Late: instrumentation + baselines (user ran two live sessions)

- P2/P1 instrumentation added: per-utterance ASR/MT/E2E timings, SPK
  playback wait, working-set memory. Getting Windows RSS via ctypes took
  three attempts (struct layout, then handle declarations) — first version
  silently returned None.
- **Baseline 1 (improvised continuous speech, ~1 min):** compute is trivial
  (~0.1s/sentence — F2 is NOT a speed problem); sentence-boundary buffer
  held with zero hallucinations under breath-pause fragmentation; playback
  backlog grows ~1s per second spoken (SPK waits to 15s).
- **Baseline 2 (same sentences read aloud):** backlog to 22s; cross-check
  against mt_smoke_results proved the garbles were ASR-side ("shuttle
  buses" → "short-tool bosses"), MT stays correct on clean text.
- **F2 design drafted (design §13)** from those numbers: steady-state ≤5s +
  catch-up rule; bounded-queue pipeline; compression ladder (length_scale,
  disfluency strip, catch-up drops; LLM summarization parked); build order.

## Lessons

- Measure before designing: the baseline reframed F2 from a speed problem
  to a compression problem in one session.
- Two humans' test styles (improvised vs read-aloud vs video) stress three
  different pipeline properties — variety in testing finds variety of bugs.

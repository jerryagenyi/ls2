# 2026-09-15 — F2 built, live-tested, and hardened in one day

## F2 build steps 1–4 (design §13.6)

- Pipeline refactored to bounded queues: segmenter → ASR+stitcher → MT →
  TTS synth → bounded playback queue → Player. Disfluency stripping
  (conservative rules; "like"/"so" preserved) + Piper length_scale 0.9 by
  default; catch-up mode behind `--catchup` (default off).

## Live run 1: YouTube video through speakers — no French audio

- User played a podcast to the mic; log showed zero SPK lines and
  `backlog max: 0.0s` despite 32 translations. Diagnosis: refactor bug —
  the TTS worker wrote PCM into a bounded `playback_q` **that the Player
  never read**; French piled up unread. The unit/model tests covered stages
  and logic but not the connections between threads. Fixed: the Player now
  owns and drains the bounded queue itself.
- Same run: filler hallucination live case #2 — "Thank you." transcribed
  from video-end silence, user confirmed unsaid.

## Live run 2: replays, with and without --catchup

- Default: backlog max 30.9s, waits to 33.5s. --catchup: bounded at 12.5s,
  9 sentences dropped (~47% retention). Catch-up verified working.
- **User pushback: 9 drops is too much** ("obliterating whole segments").
  Response (design §13.7): catch-up becomes a ladder — Tier 0 dynamic TTS
  speed-up, Tier 1 MT merge, Tier 2 local-LLM summarize (un-parked; risk
  reassessed lower because the LLM sees clean text, and Jerry's PC already
  hosts Qwen GGUFs), Tier 3 drop as last resort.
- **User's calibration question** ("is ≤5s realistic? aren't we expecting
  too much?") reframed the targets with human-interpreter data: pros run
  2–6s behind and routinely omit under density. Targets now: ≤5s
  steady-state, bounded 10–15s under dense speech, and content retention
  as a first-class metric. A guaranteed ≤5s for every word is not a real
  target — for us or for humans.
- Drops now log their full text (was an anonymous count — the user's
  "does the transcript still make sense after drops?" question exposed
  that we couldn't audit drops at all).
- New finding from the run: French didn't start until ~30s into dense
  video — no ≥0.8s pause exists in dense speech, so the first utterance
  only closed at the 30s force-flush. E2E measured from utterance END had
  been hiding this.

## Incremental ASR + Tiers 0/1 + transcript log

- User proposed read-along captions on the listener page → PRD F11;
  groundwork built: `logs/transcript-<stamp>.jsonl` with timestamped
  en/fr/dropped records.
- IncrementalASR: during unbroken speech the segmenter cuts partial chunks
  every 6s; only complete sentences commit (audio dropped, memory flat);
  unfinished tail is re-transcribed so Whisper may revise the tail but
  never a committed sentence. 30s force-flush subsumed. Unit tests for the
  commit/revise/bounded-buffer contract — writing them caught my own
  fake-Whisper being unrealistic twice (constant end-timestamps; same
  sentence forever), which is the tests doing their job.
- Catch-up Tier 0 (length_scale −0.1 while behind, floor 0.7) and Tier 1
  (merge ≤3 sentences per MT call) built.

## Live run 3: three runs, two bugs found and fixed same day

(validation/latency/2026-09-15-runs.md has the numbers)

- Incremental ASR confirmed: E2E down to 1.7–2.2s, no 30s startup wall.
- **Bug: revision duplicates** — Whisper re-emitted committed sentences on
  later passes; they reached MT twice ("exactly who this person is." ×2).
  Fixed with `drop_prefix_overlap` (leading repeats of just-emitted
  sentences dropped; genuine repeats with intervening content survive).
- **Bug: giant fragments** — dense video's speaker runs minutes without
  punctuation; the hold path flushed one run as a single fragment → one
  ~60s TTS blob → backlog spike → drops. Key insight: the user's
  "--catchup felt worse than default" was the SAME blob with different
  symptoms (drops vs 39.7s lag) — the flag didn't cause it. Fixed:
  hold-flush splits into ≤40-word pieces.
- User asked about mid-sentence language switching → design §13.9: per-chunk
  language detection at F3; session closes on a switch like a pause;
  between-sentence switches clean in ~6s; mid-sentence switch garbles the
  switch point (documented limit). Transcript log `kind` field becomes a
  language tag at F3 — no format change.
- User asked that system mechanics stay documented for developers/users →
  `docs/HOW-IT-WORKS.md` created, with the contract: updated in the same
  commit as any pipeline change.

## Lessons

- Live user testing in one day found: a silent wiring bug, two real
  algorithm bugs, a hidden 30s latency wall, and a metric blindspot — none
  of which the automated suites caught. Automated tests guard invariants;
  humans find integration reality.
- When a feature "feels worse," compare against what the alternative would
  have done — the catch-up drops and the default-mode lag were the same
  failure viewed from two sides.
- Metrics measure from a zero-point; choose the wrong zero-point
  (utterance end vs speech start) and you can't see your worst problem.

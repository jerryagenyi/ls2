# F2 round 2 — three YouTube runs with incremental ASR (2026-09-15)

Source log: `TEST-RESULT_15-9-2026_0700.md` (repo root). Three runs, two
different videos (run 1/3 denser monologue video, run 2 the same but with
`--catchup`).

## Numbers

| Run | Mode | ASR avg | MT avg | E2E avg | Backlog max | Drops | Max SPK wait |
|---|---|---|---|---|---|---|---|
| 1 (chatty video) | default | 1,473 ms | 56 ms | 1,652 ms | 10.9 s | 0 | 12.1 s |

Incremental ASR confirmed working: sentences translate while speech
continues (no more 30s startup wall); E2E improved to 1.7–2.2s.

## Findings

1. **Revision-duplicate bug (fixed same day).** Whisper re-emitted
   already-committed sentences on later passes; they reached MT twice
   ("exactly who this person is." ×2, "Lazy class. That's right." ×2).
   Fixed with prefix-overlap dedupe in IncrementalASR (unit-tested).
2. **Giant unpunctuated fragments (fixed same day).** The dense video's
   speaker runs minutes without terminal punctuation; the hold path flushed
   one such run as a single fragment → one ~60s TTS blob (the 2,027 ms MT
   line in run 2) → backlog spike → the 4 drops. The no-flag run hit the
   same blob as a 39.7s backlog. So "catchup felt worse" was really "same
   blob, different symptom": catch-up converted the spike into drops,
   default converted it into lag. Fix: hold-flush splits into ≤40-word
   pieces; both modes benefit.
3. **Video density, not the flag, drives smoothness** — run 1 (chattier
   video) stayed at 10.9s backlog with no drops and no catch-up at all.
4. ASR per-pass time grows with session length when nothing commits
   (run 2 max 9.1s pass) — expected consequence of re-transcribing a long
   un-committed tail; the fragment-split fix and dedupe reduce it. Watch on
   the next replay.
